# 日课 0.6.6 · Windows 本机签名更新包

这个包包含 0.6.6 未签名正式 APK、Android 官方签名工具及双击入口。需在你的 Windows 电脑使用原签名密钥签名，再覆盖安装手机上的正式日课。

## 你已经签过 0.6.1

1. 下载 ZIP，右键“全部解压”。不要在压缩包里运行。
2. 在同一台电脑双击“开始签名.cmd”。此前安装好的 JDK 17 可以继续用。
3. 程序自动找到并选用原签名密钥，直接在官方工具提示时输入之前的签名保护密码；不再需要按回车确认别名。随后自动签署、核对原证书身份并生成 APK。
4. 签名成功后，把 output/rike-0.6.6-release.apk 传到手机，直接安装更新，不要先卸载旧正式版。若已有同名输出，新文件名会带额外编号。

密钥继续保存在 %LOCALAPPDATA%\RikeRelease。签名包不含你的私钥、保护密码或应用资料，不会上传它们。签名密码与日课资料库主密码不同。

这个“自动签名”保留每次输入保护密码，电脑不额外保存密码。若密钥有不同的密钥库/私钥密码，按官方工具的相应提示输入。通常之前创建的 PKCS12 密钥只需输入同一保护密码。

正常更新只需运行“开始签名.cmd”。如果原 alias 记录有误，双击“修正密钥别名.cmd”，重新输入正确别名和密码；只有签署及证书身份验证通过，才保存新别名，原密钥不更换。

## 密钥未被找到或换了电脑

如果已发布过正式版，选择使用已有密钥；提供原密钥路径与原 alias。若换电脑，可把原 RikeRelease 文件夹中的 rike-release.p12、key-alias.txt、signer-sha256.txt 放回新电脑的同一路径，再运行。请用可正常工作的离线介质保管额外副本，密码另行保管。

只有从未发布正式版时才创建新密钥。密码、文件或 alias 错误会停止；候选密钥经验证后才成为默认。已有身份记录但缺少密钥时，程序禁止另建身份。

## 本轮更改

补上记录页编辑入口，纠正历史日记标题和补记日期提示，取消编辑前确认未保存修改。编辑保存失败可保留输入重试；改到较早日期后自动显示目标日期的记录。主体界面、布局和风格沿用原版。

正式包名 app.rike.offline，版本 0.6.6 / versionCode 19，最低 Android 8；沿用原签名密钥覆盖更新。

## 文件与验证

rike-0.6.6-release-unsigned.apk 是签名输入，不能直接安装。脚本固定校验 APK、apksigner.jar 和 RikeLocalTool.java 的 SHA-256。成功输出包含已签名 APK 和证书校验回执，签名身份必须与以前一致。BUILD-INFO.json 记录精确构建来源与检查结果；SHA256SUMS.txt 记录包内文件校验值。

RikeLocalTool.java 仅编码非秘密路径以兼容中文与空格路径。签名密码由官方工具交互读取，不经过辅助代码或脚本参数。工具来源与许可见 THIRD-PARTY-NOTICES.txt、LICENSE-apksigner.txt。

如果 JDK 找不到，安装官方 Temurin JDK 17 或更高版本：https://adoptium.net/temurin/releases/?version=17&os=windows&arch=x64&package=jdk

覆盖安装需要与旧正式版相同的包名和签名身份。签名前可在旧应用导出并验证加密备份；不要为解决安装问题先卸载含资料的旧版。真机拖动手感、指纹及系统输入法需要手机上核对。
